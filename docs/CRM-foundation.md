# CRM 一期改造

基线：GitHub dev 4f1279685fbb40f8763ebd619a6a2630cb4f1680，尚未核实线上部署版本。

## 权限默认值

| 角色 | 数据范围 | 默认动作 |
| --- | --- | --- |
| 销售 | 本人 | 查看、新建、编辑 |
| 主管 | 所属团队 | 查看、新建、编辑、分配及交接 |
| 管理员 | 全部 | 按显式授权执行客户操作；系统配置另行授权 |

导出、删除、恢复独立授予，不由查看权限推导。团队成员和角色由服务端读取，不能由请求体指定。交接双方均须在操作者的授权范围内，接手账号须启用。

## 单条写入切换

1. 核对部署提交、备份并验证现有快照和明细表一致性；明确唯一数据源，不继续双写两套权威状态。
2. 新接口按客户 ID 读写，并用该客户的版本做条件更新。不同客户的修改互不冲突；同一客户过期写入返回 409。批量导入、转移、删除和恢复分别走显式操作。
3. 前端和服务端一起切换。旧全量写入须停用，避免旧客户端覆盖新记录。不能只过滤旧接口读取结果后保留全量写入。

## 交接验收

交接原因、最近进展、下一步和截止时间必填。负责人变更、未完成任务转移和交接日志同一事务提交；历史跟进和报价保留原作者。新负责人可查看待办和交接历史，旧负责人按其现有权限访问。测试失败时，负责人、待办和日志均不得部分写入。

## 当前实现与启用限制

已加入默认关闭的客资列表、单条 GET/PATCH 和交接接口、行版本及交接表迁移。PATCH 只允许基本资料字段，不能改负责人或历史。主管只有显式查看全部授权才可跨负责人读取，有转移授权才可执行交接；团队范围尚未接入。普通销售只读取本人客资。

不要在现有站点设置 CUSTOMER_ROW_API=enabled：启用后旧客资整表读取和写入均返回 410，而现有前端仍依赖它们。正式切换前须完成明细表与快照对账、新建及删除恢复接口、前端迁移、团队范围及真实数据库验收。回滚也必须处理新旧数据差异，不能直接重新开放旧快照写入。

本地 HTTP 回归使用内存 SQLite 和 D1 适配器，覆盖登录、跨账号读写隔离、交接和旧接口禁用，不连接线上。
